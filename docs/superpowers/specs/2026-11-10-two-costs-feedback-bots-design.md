# Two costs, and bots that use feedback — design

Status: approved in conversation 2026-11-10 ("yes, listing and hosting. write the spec").
Source: instructor review of the live game (Nov 2026): simplify costs; prove that Marketing's feedback
matters by comparing bots with and without it; feedback should bring teams closer to the ideal, not all at once.
Builds on `fix/feedback-variety-hints` (each joke's feedback shows different criteria; missed ordered
criteria carry a direction, LOWER or HIGHER). Both repos.

## 1. Goal

1. **Simpler money.** Two costs only, both owned by Marketing. The Joke Maker pays nothing.
2. **Evidence that feedback matters.** Bot classes where matched teams differ only in whether they use
   Marketing's feedback, so we can show (or disprove) that feedback, and fast feedback from small
   batches, improves jokes and profit.

## 2. Two costs

| Keep | Charged when | Owner | Lesson |
|---|---|---|---|
| **Listing** (`cost_of_publishing`) | Once per joke Marketing releases | Marketing | Releasing is a decision with a cost |
| **Hosting** (`hosting_fee_per_joke_minute`) | Every minute a released joke has not yet sold (from release to first sale, or round end) | Marketing | Unsold stock is waste |

Everything else is 0 by default: shipping (all three tiers), storage, discard.

```
Profit = Sales × price − Listing − Hosting
```

**Why this still teaches Lean.** With no shipping there is no setup cost, so the best batch is small
(the Lean ideal). Round 2's advantage comes from flow and feedback: a small batch reaches customers
sooner (customers arrive over the round, so a late joke misses buyers) and returns feedback sooner.
Holding a batch on Marketing's desk no longer has a fee, but it still loses the customers who arrive
meanwhile.

**Amounts.** Starting values listing $0.10, hosting $0.05 per joke-minute; final defaults come from the
sweep in §5. Both stay editable per class.

### 2.1 Backend

- Defaults (`domain` defaults, admin login, Reset Game, config-created rounds): shipping 0 / 0 / 0,
  storage 0, discard 0; listing and hosting from §5.
- No migration: the columns stay, the API still accepts every fee (rollback and pilot knobs). The profit
  formula is unchanged; zero fees simply contribute nothing.

### 2.2 Frontend — only two costs anywhere a person looks

- **Joke Maker:** no cost copy at all. The shipping line under the paste box is removed.
- **Marketing:** "Fees and wait times" lists Listing and Hosting only. The wait timeline keeps "With
  Marketing" and "Waiting for first buyer", without "storage is charged".
- **Next step (Marketing, desk wait):** "Batch waiting {n} s. Release what's good enough: customers
  arriving now can't buy it." (no storage price).
- **Tour:** the Joke Maker's shipping step becomes a batch-size step: Round 1 "Every batch is 5 jokes.
  Keep them coming." Round 2 "You choose the batch size now. Smaller batches reach customers and come
  back with feedback sooner." Marketing's fee step: "Every joke you release costs {listing} to list, and
  {hosting} a minute while it sits unsold. Release jokes that will sell."
- **Instructor:** Setup → Costs shows Listing and Hosting only. Live/Debrief: fee columns and the
  "Where the money leaked" chart show Hosting, Listing on never-sold jokes, and nothing else; class
  totals "Fees" = listing + hosting.
- **Rule:** a fee whose amount is 0 for the round is not shown anywhere, so an old round with shipping
  still displays it, and a class that sets storage back above 0 sees it again.
- Guide (`docs/lean-market-mode.md`) and the instructor doc updated to two costs.

## 3. Bot jokes with known traits (local tests only)

Today local bot jokes get a random hash score, so feedback on one joke says nothing about the next. A
person can act on feedback because they control what they write; bots need the same.

- **Trait corpus.** A generated, versioned file of synthetic jokes (target 1,000), each with a category
  for all 11 matched criteria and a title. Text length matches its Length category (word counts per
  `core/domain/scoring/length.go`). Generated by a script in the frontend repo; one copy is committed to
  each repo, and a test fails if the copies differ.
- **Trait classifier.** A new local-only classifier mode `APP_LLM_MODE=traits`, behind the same explicit
  confirmation guard as the hash classifier (`APP_LLM_HASH_CONFIRM=local-pilot-only`). A joke whose text
  is in the corpus gets the corpus categories (Title Fit graded "Strong"); any other text falls back to
  the hash classifier. Never used on the live site.
- **The bot knows its own jokes' traits** (as a writer knows they wrote a long pun). It never sees the
  ideal joke or any fit score.

## 4. Bots that use feedback

**The loop, as people would run it:**

1. After a release, the **Marketing bot** reads the team's customer feedback (the same endpoint and fields
   the screen uses: landed, missed, direction hints).
2. It sends the Joke Maker a **note** with the next batch it releases, in plain words, e.g.
   `Keep: Topic, Length. Change: Humor Style, Energy. Length: shorter.`
3. The **Joke Maker bot** reads the latest note from Marketing (the same field the Joke Maker screen
   shows) and updates its picture of what customers want:
   - a landed criterion: keep that joke's category for it;
   - a missed categorical criterion: avoid that category;
   - a missed ordered criterion with a direction: move one step that way;
   - criteria nobody mentioned: unchanged.
4. Its next batch takes the corpus jokes that best match that picture (ties broken by the run's seed;
   no joke text repeated within a round).

**Feedback off** = the same persona, pace, batch sizes and seed, except the Joke Maker ignores notes and
picks corpus jokes by its seed only, and Marketing sends no note.

Feedback use is a per-team option (`useFeedback`), not a new persona, so any persona can run with it on
or off. The bot panel does not show it; it is a pilot option.

## 5. The comparison and the cost sweep

**Design (one class = 20 teams, local stack, trait classifier, bots at 10×, 90 s window = 15 min):**

| Group | Teams | Round 1 batch | Round 2 batch | Feedback |
|---|---|---|---|---|
| Small + feedback | 5 | 5 | 3 | on |
| Small, no feedback | 5 | 5 | 3 | off |
| Large + feedback | 5 | 5 | 10 | on |
| Large, no feedback | 5 | 5 | 10 | off |

Teams are matched in pairs (same seed, same Balanced pace), so each "on" team has an "off" twin that
draws the same starting jokes. Every run uses a fresh seed; the report averages 3 classes per setting.

**Measured per group and round** (the pilot computes fit from corpus traits and the round's ideal with a
TypeScript port of the Go scoring rules, tested against shared fixtures; bots never see it):

- mean fit of released jokes by batch number (the learning curve);
- batches until a released joke first clears the customers' bar;
- share of released jokes above the bar; sales; listing; hosting; profit; send → first sale.

**Success checks (PASS/FAIL in the report):**

1. Feedback teams' mean fit rises from their first to their last Round 2 batches; no-feedback twins' does not.
2. In Round 2, feedback teams earn more profit than their no-feedback twins.
3. The feedback gain is larger for small batches than for large ones.
4. Feedback is gradual: a feedback team needs at least 3 batches to first clear the bar (not solved in one).
5. With the chosen costs, about half of teams or more finish Round 2 in profit, and a team releasing
   everything spends 40–60% of its Round 1 revenue on fees.

**Cost sweep.** The same class run on listing {$0.10, $0.25, $0.50} × hosting {$0.05, $0.10, $0.20}
per joke-minute, 3 classes each. The defaults are the cheapest setting that passes checks 2, 3 and 5.
If check 4 fails (feedback solves the puzzle too fast), the knobs are the number of jokes per feedback
(`feedback_joke_count`, default 3) and criteria shown per joke (5), not the costs.

## 6. Done when

- Both repos' suites pass; the trait corpus copies match; the trait classifier refuses to start without
  its confirmation.
- No zero-amount fee appears on any screen, in the tour, or in Next step; a round with a non-zero
  shipping or storage fee still shows it.
- A pilot report with the comparison and the sweep is committed under `docs/pilots/`, and the chosen
  listing and hosting become the defaults.

## 7. Out of scope

Exporting class results (a separate request from the same review), the real AI classifier's behaviour,
changes to how customers buy, and the Learner persona (unchanged; it learns from sales, not feedback).
